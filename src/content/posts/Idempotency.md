## 一、初识幂等

### 1、什么是幂等

- 在计算机科学和网络通信中，幂等指一个操作无论执行多少次，其结果都是一致的
- 换句话说，对于**相同**的输入，无论进行多少次重复操作，都应该保持其**结果一致**

![1](/images/Idempotency/1.png)

数学来源：
$$
f(f(x)) = f(x)
$$
哪操作会导致幂等？

- 读：不对底层数据产生变化，天然支持幂等

  ```
  如 HTTP: GET
  ```

- 写：会修改底层数据，无法保证幂等

  ```
  如 HTTP: POST/DELETE/PUT
  ```

### 2、幂等产生的原因

在 Web 应用程序中，导致幂等的原因一般分为：

- 网络延迟导致的请求重试
- 前端用户的重复操作请求
- 第三方中间件的重试机制（如 MQ）

当重复请求（相同输入的重复操作）进入系统中时，如果接口不具备幂等性，可能会导致：

- 状态不一致
- 数据重复提交

#### （2）消息重复消费

![5](/images/Idempotency/5.png)

当消费者出现异常后，默认策略是消息会不断 requeue（重新入队）到队列，再重新发送给消费者，然后再次异常，再次 requeue，无限循环，导致 mq 的消息处理飙升，带来不必要的压力

我们可以利用 Spring 的 retry 机制，在消费者出现异常时利用本地重试，而不是无限制的 requeue 到 mq 队列

```
spring:
  rabbitmq:
    listener:
      simple:
        prefetch: 1
        retry:
          enabled: true # 开启消费者失败重试
          initial-interval: 1000 # 初始的失败等待时长为1秒
          multiplier: 1 # 下次失败的等待时长倍数，下次等待时长 = multiplier * last-interval
          max-attempts: 3 # 最大重试次数
          stateless: true # true无状态；false有状态。如果业务中包含事务，这里改为false
```

## 三、面试

### 1、说说你对于幂等的理解

- 相同输入的重复操作，其结果应该保持一致
- 如 HTTP 的读操作，如 GET 协议天然就是支持幂等，而对于写操作，如 POST / PUT / DELETE 是需要程序员做幂等处理的

### 2、有哪些常见的幂等场景

- 网络延迟导致的请求重试
- 前端用户的重复操作请求
- 第三方中间件的重试机制（如 MQ）
